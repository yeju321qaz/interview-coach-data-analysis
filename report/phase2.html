2단계 작업 결과 — 검수 준비·STT 비교·녹음 계획 보완

기준일 2026-10-29. 기존 분석 수치와 원본·기존 검수 CSV·녹음 계획은 보존했다. 기존 웹사이트에는 별도 섹션만 추가했다. 이전 2단계 작업 당시에는 사람 검수·STT 모델 실행을 하지 않았다. 최신 tiny 시험은 상단의 실제 실행 결과로 구분한다.

1. 사람 검수가 필요한 표본

기존 275행에서 48행을 선정했다. 12개 규칙 유형 기본 3행씩, 주요 4유형에 2행씩 추가, 미분류 4행이다. 복수 유형 행은 한 선정 층에만 배정했으며 자동 유형 전체는 유지했다. 청취 가능한 표본은 45행, 품질 플래그가 있는 표본은 2행이다. 음성 비교를 많이 할 수 있도록 음성 보유 행을 우선했다. 이는 유형별 초기 검수용 표본으로 모집단 오류율을 추정하는 비례 확률 표본이 아니다.

2. 검수 화면

report/review.html을 열고 검수자 ID(R01 등)를 입력한 다음 review/review_subset48.json을 고른다. 사람은 질문 유형(복수), STAR 적합성, QA 관련성, 전사–음성 일치, 활용 품질, 근거를 입력한다. 원본 WAV가 있으면 화면에서 재생할 수 있고 완료 전에 청취 확인이 필요하다. 자동 결과는 기본 접힌 상태로 제공하며 독립 판정 후 펼쳐 비교한다.

완료 버튼을 명시적으로 누르고 필수 값이 있어야 ‘단일 검수 완료’다. 입력 변경 시 다시 작성 중으로 돌아간다. 입력은 검수자 ID별 브라우저 로컬 저장소에 임시 저장하며 CSV 내보내기·복원이 가능하다. 미작성 행도 미검수로 내보내고 한 사람의 판단을 두 사람 합의 정답으로 표시하지 않는다. R01/R02는 별도 ID·CSV로 검수하고 review/compare_reviews.py로 비교한다. 서로 다른 유형·STAR·관련성·전사 판정은 별도 재판정 파일로 보낸다.

CSV/HTML에 원문을 내장해 공개 배포하지 않도록 페이지는 사용자가 선택한 로컬 JSON만 읽는다. 서버로 데이터를 보내는 기능은 없다. 로컬 저장소에는 검수 결과·근거가 남으므로 공유 PC에서는 CSV 확보 후 해당 사이트 저장소를 정리한다. 음성 재생은 프로젝트 내 data 경로가 유지돼야 한다.

3. STT 비교와 실행 가능 여부

후보는 faster-whisper(로컬 다국어 Whisper), Google Chirp 3, Azure Speech Standard다. 자세한 기능·공식 출처·비용·실험 절차는 STT_비교_실험계획.md를 참조한다. 한국어 CER·간투사 보존율·응답 지연은 모두 미측정이다.

보유 WAV 6개 하위셋에서 2개씩 12개·14.4732분을 선정했다. 경로·해시·길이·AI Hub 전사와 빈 교정 전사 칸은 stt/manifest12.csv에 있다. 현재 정답 전사 12개 모두 청취 검수 전이다.

실행 코드는 기본 dry run으로 형식·해시만 검사한다. 로컬은 기존 모델 폴더만 허용하고 자동 다운로드를 막았다. 클라우드는 유료 실행 및 외부 전송 승인 플래그가 있어야 진행한다. 이번에 API 호출·STT 모델 다운로드·STT SDK 설치는 하지 않았다. SDK 호출 어댑터는 실제 공급사 응답을 아직 검증하지 않았으므로 승인 후 1파일 시험이 필요하다. CER 구현 검증은 합성 문자열 단위 검사이며 모델 성능 실험이 아니다.

4. 신규 녹음 계획 수정

collection/recording_plan_80_v2.csv는 기존 80행의 화자·질문·목표 유형·분할을 유지하고 순서·기록 항목을 보완한 별도 사본이다. Williams 4가지 순서로 유형별 등장 위치와 직전 유형을 균형화했다. 120초 목표 휴식·이전 답변 열람 금지·4회 종료 전 피드백 금지·실제 연습 횟수 기록을 제안했다. 기억 효과의 제거를 검증한 것은 아니다.

모든 행은 지시가 있는 시나리오로 표시했다. 실제 이벤트가 지시에 의한 것인지 우연히 발생했는지는 사람이 따로 기록한다. 정상 20행에서 자연 이탈을 관찰할 기회는 있으나 자연 이탈 데이터가 이미 생긴 것은 아니다. 성장 리포트의 자연 답변→피드백→재답변은 별도 후속 데이터가 필요하다.

계획 ID 기준 화자·질문군 분리는 통과했다. 그러나 의미 질문군의 두 사람 검수와 실제 화자 확인은 미완료다. 테스트는 32건·유형별 8건으로, 유형별 한 건이 12.5%p를 바꾼다. 개선 상세는 녹음계획_보완.md에 있다.

2. 표본과 실행 전 조건

보유 답변 WAV 1,198개가 속한 6개 하위셋에서 길이 정렬의 약 25%·75% 위치를 하나씩 골라 12개, 약 14.4732분을 선정했다. stt/manifest12.csv에 경로·SHA-256·길이·음량·침묵·규칙 간투사 비율·질문·AI Hub 전사를 담았다. 원본을 복사·수정하지 않았다. 표본은 보유한 직군/성별/경력 조합을 고르게 확인하기 위한 소규모 편의표본이며 전체 한국어·지원자·잡음 환경을 대표하지 않는다. 화자 고유 ID를 몰라 12명이 서로 다른 사람이라고 보장하지 않는다.

원본 전사는 source_reference에 보존했고 reference_corrected, reference_reviewer, reference_status는 사람이 청취 후 작성한다. 현재 모두 unreviewed다. 청취 검수가 끝나면 status를 human_verified로 바꾸고 교정 전사를 입력한다. 원본 전사로 산출한 값은 임시 참고치로만 표시하고, 사람이 검수한 전사 기준 결과와 섞지 않는다.

기본 실행은 dry run으로 WAV 형식·해시·분량만 확인한다. API 전송·모델 불러오기·자동 다운로드는 하지 않는다. 현재 faster-whisper 패키지와 Whisper 모델은 로컬에서 발견되지 않았으며, 두 클라우드 SDK도 이 단계에서 설치·인증 시험하지 않았다. 실제 실행에는 다음 확인이 필요하다.

  • 로컬: 별도 환경의 faster-whisper와 이미 내려받은 변환 모델 디렉터리. 모델 다운로드가 필요하면 크기·저장 위치를 먼저 확인한다. 코드에 자동 다운로드는 없다.
  • Google/Azure: 공급사 키·프로젝트·리전·결제 설정, AI Hub 데이터의 외부 전송 허용 범위와 사용자의 유료 실행 승인. 인증정보는 환경변수로만 읽고 파일·보고서에 저장하지 않는다.
  • Google 기본 단가를 단순 적용한 12개 1회 예상치는 약 USD 0.232다. 이는 실측 청구액이 아니며 재실행·반올림·계약·부가 서비스·세금 등을 포함한 최종 견적은 아니다. Azure 금액은 단가 확인 전 계산하지 않는다.

3. 제공 코드와 비교 조건

stt/experiment.py는 실제 호출용 어댑터와 공통 CER 평가기를 제공한다. SDK/모델의 실제 응답은 아직 시험하지 않았으므로 인증 후 1파일 smoke test부터 실행한다. 오류 시 멈추고 자동 재시도로 비용을 늘리지 않도록 했다. 출력 경로가 이미 존재하면 덮어쓰지 않는다.

세 경로 모두 외부 질문 원문·정답 전사를 모델 힌트로 주지 않는다. Google/Azure의 내부 정규화·문장부호 정책과 로컬 Whisper의 설정은 동일하게 만들 수 없으므로 설정을 기록하고 결과 차이에 포함해 해석한다. 클라우드 모드의 wall/audio 비율에는 실제 재생 대기가 포함되므로 로컬 처리 속도와 직접 순위를 매기지 않는다. 지연은 구간별 값과 파일별 p50/p90을 보관하고, 음향적 발화 종료를 사람이 찍은 지연과 공급사 종료시각 기준 지연을 구분한다. 음성 끝 offset이 이상하면 음수 지연을 임의로 0으로 보정하지 말고 로그를 검사한다.

4. 평가 지표

CER은 양쪽 모두 NFC·영문 소문자화·공백 및 Unicode 문장부호 제거를 대칭 적용하고, 숫자/영문 발음을 임의 치환하지 않는다. 간투사도 삭제하지 않는다. CER=(치환+삭제+삽입)/정답 문자 수로 계산하며 micro(오류 합/문자 합)와 macro(파일별 평균)를 모두 제시한다. 빈 정답은 오류로 처리하고, 실패·누락·미검수 정답 파일 수를 숨기지 않는다. 다른 모델이 성공한 파일만 골라 비교하지 말고 동일한 12파일의 실행 상태와 공통 성공 집합을 함께 보고한다.

간투사 Recall은 청취로 확인한 실제 간투사 이벤트의 보존 비율이다. filler_spans.csv에 검수된 정답의 정규화 후 0부터 시작하는 [ref_start,ref_end) 문자 위치와 원문·검수자를 적는다. normalize()로 확인한 문자열에서 위치를 정한다. 평가기는 편집거리 정렬에서 해당 문자열 전체가 연속·동일하게 보존됐는지 센다. 반복하는 ‘어’의 정렬은 여러 최적해가 가능하므로 애매한 사례는 사람 확인이 필요하다. ‘그·좀·이제’는 의미어일 수 있어 규칙 토큰 수만으로 정답을 만들지 않는다.

간투사 Precision은 예측문에도 문맥 판정이 필요해 자동 산출하지 않는다. hyp_filler_audit.csv에 예측 간투사의 문맥 판정과 정답 이벤트 연결을 적어 별도 합산한다. 전체 예측 간투사를 빠짐없이 검수하기 전 분모가 불완전하므로 Precision을 공개하지 않는다. 현재 이 두 양식도 빈 상태이며 보존율을 작성하지 않았다.

기존 80건 녹음 계획 보완

2026-10-29. 기존 verification_20261029/collection/recording_plan_80.csv와 수집·라벨링 계획은 보존했다. 수정안은 collection/recording_plan_80_v2.csv이며 녹음 건수·화자 ID·질문·목표 유형·개발/검증/테스트 배정은 동일하다. 신규 녹음 완료 수는 0건이다.

1. 배분과 순서·기억 효과

20명 × 4유형 = 80건을 유지한다. 정상/지속 이탈/일시 이탈 후 복귀/STAR 누락은 각각 20건이며, 개발 32건(유형별 8), 검증 16건(유형별 4), 테스트 32건(유형별 8)이다.

단순 순환 순서 대신 네 가지 Williams 순서를 5명씩 배정했다. A=정상, B=지속 이탈, C=일시 이탈, D=STAR 누락일 때 순서는 A-B-D-C / B-C-A-D / C-D-B-A / D-A-C-B다. 전체와 각 분할에서 유형별 등장 위치가 균형을 이루며 직전 유형의 영향도 균형화한다. 이는 실험 설계상의 균형이며 기억 효과가 사라졌다는 측정 결과가 아니다.

같은 질문을 반복하므로 뒤 순서가 더 유창해지거나 앞 답변을 외울 수 있다. ① 본 녹음 전 다른 질문으로 장비 연습 1회, ② 직전 녹음·전사 재열람 금지, ③ 4회 종료 전 코치 피드백 제공 금지, ④ 회차 사이 목표 120초 휴식(실제 시간 기록), ⑤ 각 시나리오 안내는 해당 차례 직전에 제공한다. 휴식 120초는 실행 가능한 시작안이지 효과가 검증된 간격은 아니다.

v2 표에는 previous_collection_order, collection_order, order_group, first_exposure, previous_answer_access, inter_trial_break_target_s, actual_break_s, feedback_before_next, rehearsal_count, memory_effect_notes를 추가했다. 실제 수집 시 미준수·중단·재녹음도 기록한다. 첫 노출 답변과 이후 답변을 별도로 살펴보며 이 작은 표본으로 순서 효과의 통계적 제거를 주장하지 않는다.

2. 연기한 이탈과 자연 이탈

80건은 모두 지시가 있는 통제 시나리오이므로 elicitation_mode=scripted_condition으로 표시했다. 정상 조건도 ‘자연 발생 데이터 20건 확보’라고 부르지 않는다. 각 이탈 이벤트의 observed_drift_origin에 instructed, spontaneous, uncertain을 사람이 실제 녹음 근거로 기록한다. 필요 시 기존 drift_events 양식에 같은 열을 추가한 사본을 사용한다. 시나리오 목표와 실제 발생 라벨은 분리한다.

정상 조건 20건은 참가자가 자기 경험을 자유롭게 말하도록 하여 자연 이탈을 관찰할 기회로 활용한다. 별도 이탈 유도는 하지 않는다. 우연히 발생해도 수집자가 지시하지 않았는지·왜 무관한지 라벨러 2인이 확인하고 spontaneous로 표시한다. 정상 조건이 첫 차례인 표본은 5명뿐이며 나머지는 다른 조건을 경험했으므로 이를 별도 표시한다. 관찰된 자연 이탈이 0건이면 자연 이탈 정답 데이터 0건으로 보고한다. 자연 이탈 Recall을 계산하기 위해 연기 데이터를 자연 이탈로 재분류하지 않는다.

발표에서는 연기한 시나리오의 탐지 성능과 자연 발생 성능을 분리한다. 이번 80건을 늘리지는 않으며, 자연 이탈 확보가 부족하면 일반화 검증은 후속 과제로 둔다.

3. 분할 검증

validate_split.py는 화자와 질문군을 연결한 그래프의 연결요소가 둘 이상의 분할에 나타나는지 검사한다. 계획 ID 기준으로 화자 20명·질문군 20개가 분리돼 있다. 서로 다른 질문군 ID가 의미상 독립이라는 보장은 아직 없다. 실제 참여자 중복 여부도 미확인이다.

예를 들어 F001 ‘팀 갈등 조정’(개발)과 F010 ‘반대자 설득’(검증), F008 ‘품질 개선’(개발)과 F015 ‘피드백 수용’(테스트)은 의미 중복 여부를 사람이 점검할 후보다. 이 두 쌍을 동일 질문군이라고 확정한 것은 아니다. semantic_family_map.csv에 두 라벨러가 검토한 최종 의미 질문군을 입력하고 다음 명령으로 다시 검사한다.

& $verificationPython phase2_review_stt_20261029/collection/validate_split.py --family-map phase2_review_stt_20261029/collection/semantic_family_map.csv --output phase2_review_stt_20261029/collection/split_check_semantic.json

모든 20개 질문군의 최종 매핑과 검토자를 채운 뒤 실행한다. 분할 충돌이 생기면 녹음 전에 같은 의미 질문군의 전체 연결요소를 같은 분할로 이동하거나, 한쪽 질문을 다른 의미 질문으로 교체한다. 그 후 분할별 유형 균형을 다시 점검한다. 검증 편의를 위해 실제 검토되지 않은 의미 매핑을 자동 작성하지 않았다.

실제 수집 후 actual_speaker_id와 actual_question_family_id를 채워 재실행한다. 계획표 통과와 실제 데이터 분리 완료는 구분한다. 테스트 정답은 담당자만 보관하고 최종 정책 고정 전 개발자가 열지 않는다. 기존 AI Hub의 화자 고유 ID는 확인되지 않았으므로 그 데이터의 화자 독립성을 대신 보증하지 않는다.

4. 작은 테스트 표본과 성장 리포트

테스트는 유형별 8건이고 한 건이 해당 유형 Recall 12.5%p를 바꾼다. 같은 화자의 4건은 독립 표본이 아니다. 유형별 분자/분모·95% 구간을 병기하고 화자 단위 불확실성을 살핀다. 집단별 공정성·작은 성능 차이·실제 사용 환경 전반에 대한 확정적 결론에는 부족하다.

의도적으로 답변 내용을 바꾼 4개 시나리오를 반복 연습의 향상 데이터로 사용하지 않는다. 성장 리포트에는 동일 화자·질문·평가 기준으로 자연 답변 → 피드백 → 재답변을 별도로 수집해야 한다. 이번 80건에는 추가하지 않고 선택 후속 과제로 남긴다. 실제로 진행할 경우 피드백 버전·연습 간격·연습 횟수·사람 전후 평가를 기록하고, 같은 화자/질문은 하나의 분할에 유지한다.

5. 기존 라벨 원칙 유지

이탈 구간 [start_s,end_s), 복귀 시각, 알림 허용창, STAR 근거 구간, 라벨러 2인의 독립 판단과 제3자 재판정은 기존 계획을 따른다. 실제 녹음 유형·불명확성·누락 요소는 지시한 시나리오를 그대로 복사해 정답으로 만들지 않는다. 필수 변경은 80건 v2의 순서·추가 기록 열이며, 원본 양식에 입력된 라벨은 덮어쓰지 않는다.
